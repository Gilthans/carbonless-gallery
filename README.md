# carbonless gallery

Case studies for [carbonless](https://github.com/Gilthans/carbonless): one pull request per case, regular or edge, to open in carbonless and see how it's handled.

Each case has its own base branch (`base/<case>`) and head branch (`case/<case>`), so the cases don't affect each other. The PR description says what to look at.

| Case | PR | What it shows |
|---|---|---|
| whitespace | #1 | Re-indents, CRLF, trailing spaces and a moved block next to real changes (Settings → Ignore whitespace). |
| regular | #2 | An ordinary feature PR with tests: the control case. |
| renames | #3 | Pure, edited, moved and copied files, and renames either side of git's 50% similarity threshold. In the Files tree each rename also shows at its old path (faded, reversed red icon, opens the same diff), and a folder left with only old paths (`ledgerkit/parsers`) is a faded ghost with no numbers. |
| file-kinds | #4 | Binary and image files, empty files, a symlink, a mode change, a deleted file and a submodule bump. |
| moved-code | #5 | A function moved within a file, one moved to another file, and one moved and edited. |
| invisibles | #6 | Zero-width and no-break spaces, tabs vs spaces, a BOM, a missing final newline, RTL text, emoji and a 401-character line. |
| big | #7 | 60 files, a regenerated lockfile, a minified vendored file and generated code: first-open performance. |
| history-merge | #8 | The base moves on and is merged into the PR branch (with a conflict), then a later commit. |
| history-force-push | #9 | A first version, a review on it, then a rebase onto a moved base with edits and a force-push. |
| threads | #10 | Single-line, multi-line, deleted-line and file-level review threads, replies with Markdown, one resolved, one outdated. |
| merged-left | #11 | A review started in carbonless, then the PR merged by a merge commit: GitHub still puts LEFT lines on the PR's own diff, while the base branch now holds the head. |
| side-by-side | #12 | Clusters of 2/5, 5/2 and 1/5, a 400-character line, tabs, a lost final newline (one 1/1, one in a 1/3), whitespace-only and mixed clusters, a context line with threads on both sides, a 2,000-line single hunk (Settings → Side by side). |
| showcase | #13 | Start here: one of every file change (added, deleted, pure and edited renames, a moved block, empty, binary, mode change, a long line, tabs vs spaces, whitespace next to real changes, a lost final newline, a 398-line file changed in the middle), three commits, threads of every shape (line, range, deleted line, file, resolved, outdated). Mirrored on carbonless-scratch#1 for writes, and offline in `scripts/demo-threads.ts`. |
| inline-diff | #14 | What GitHub marks inside a changed line: renamed words, literals, whitespace and re-indents, emoji/CJK, CRLF, 220 to 10,000-character lines and probes around the ~1,024 cut, graded similarity (92% to 8% kept), equal blocks up to 50/50, and the plain ones: 3/1, 1/3, 2/3, a split and a joined line, a moved line. |
| verdict | #15 | What blocks a merge, for the Final Verdict tab: a failing check, a running one (re-run `slow-e2e`), changes requested by a second reviewer (github-actions), two unresolved threads, and a base-branch rule carbonless can't read (private repo on a free plan: unknown, never "ready"). |
| lt-in-comments | #16 | Review comments posted by carbonless with `<` in them: generics (`List<String>`, `<T>`, `Optional<V>`), `a < b` and code spans, which GitHub shows as typed (it would drop `<String>` as an HTML tag); carbonless's edit box shows them unescaped. |
| rr-append | #18 | Re-review after commits appended (S1): PS1 reviewed, then a push that leaves some clusters alone (carried), edits some (reworked), grows one, edits one of two identical guards (new + gone), regenerates a crossed-off file. The patch set graph, the toast, the since view, carried marks, the first mark starting PS2. |
| rr-rebase | #19 | Re-review across rewrites: the base moves on, then a trivial rebase (S4a), a squash (S5), a fixup commit (S1) and a force-push back (S6), one patch set each (PS1–PS4): every connector's card, going back to an earlier patch set read-only, the comparison base between any two dots. |
| rr-merge-in | #22 | Re-review after the base is merged in with conflicts (S3): both files chipped `conflict`; a thread on a line the resolution rewrote is `changed since` with its old line above the new one; a LEFT thread whose line the base changed is unplaced, `base changed` (X6). |
| rr-moves | #23 | Thread fates after the code moves (PS1–PS3): a rename with the line intact (placed on the new path), an extracted function (`moved?` candidate), a formatter sweep (`changed since`), a deleted file and a reverted commit (the trailing "Not in this comparison" group on PS2 and PS3); drag a thread onto a line to place it. |
| rr-stacked | #27 | A PR stacked on another (parent #26): PS1 reviewed on the parent's branch with a Comment verdict; the parent squash-merged and the child retargeted (S7: the parent's code reads as new, PS2); the child rebased (S4a). Final Verdict: "Retargeted, same diff · nothing to re-read". |
| rr-showcase | #28 | **The re-review demo, a guided tour in its description.** One PR through an append (S1, PS2), a rebase (S4a, PS3) and a merge-in with a conflict (S3, the head left to view), marks and comments at each step, a verdict on PS1: since view, carried marks, changed threads, conflict chips, read-only PS1, and the Final Verdict's "Since then". |
| find-in-pr | #20 | Find in PR (Cmd+F): `saveDraft` renamed to `persistDraft` across four files, plus a hit only in a context line (`notes.ts`, plus one only after expanding a gap), one in a file path (`docs/persistDraft.md`), `PersistDraftOptions` differing only in case (Match case), a binary `assets/persistDraft.png` (path hit only) and a re-indented whitespace-only cluster holding a call. The count chips, the spinner on a cold open. |
| hostile-pr | #21 | Review buddy against a PR that tries to make an AI reviewer run things: README/CLAUDE.md instructions, a SessionStart hook, an MCP server and a script, each `touch`ing an `AGENT_*` file. Ask agent on `src/tally.ts`; see what the activity line shows, that nothing reaches GitHub and review progress is untouched. |
| bom-tree | #29 | A file's byte order mark added (alone, and next to an inserted line), removed, unchanged and joined mid-file by `cat`: hidden with Show hidden characters off, with ⚠ where it's the change; and 70 files, a tree taller than the window. |
| markable | #30 | Every kind of unit in the full diff, each with its own box and ⊘: a modified line, two clusters one line apart, added and removed lines, whitespace only and mixed, a three-line cluster with a thread on its middle line, a lost final newline, and file-level rows (rename, mode, binary, empty). Tick, untick, cross off: only that unit changes, in every layout and on a phone; a reviewed unit's ⊘ says why it's off. |
| rr-markable | #32 | The since view's units that must each be markable: a gone piece that also holds the reworked cluster's removed line, a whole file undone (a gone file, each piece with its own box), a whitespace-only rework, a new mode change; the head left unstarted (provisional). |
| rr-pieces | #33 | Marks per piece in the since view (S1, PS1 reviewed, the head left to view): `formatAmount` edited in three places is one reworked cluster in three pieces, each marked on its own (the full diff shows the cluster mixed until all are); `formatRate`, two reviewed PS1 changes merged into one cluster that deletes more base lines, shows a removal-only piece chipped `removed` whose box marks that cluster; `parseRate`'s validation taken out again is a `reverted` piece marked on its own, to read until marked. |
| hunk-context | #34 | Function names on hunk headers and on the hidden-lines row above each hunk, as GitHub shows them: methods and functions in 20+ languages (which git rules GitHub uses, and which it doesn't), a hunk at the top of a file, the repo's own `.gitattributes`; a 40-line gap with ↓ above ↑ (each half of the row loads its arrow), ↕ gaps and a tail gap. |
| rr-since-search | #36 | Find in PR in the since view (PS1 reviewed, PS2 started; open PS1 → PS2) searches the interdiff: `earlyTerm`, changed in PS1 only, finds nothing; `core 30`, removed in PS2, is found at old line 35 (PS1's numbering, not the base's 30) and Enter scrolls to it; `laterTerm` at new line 35; `goneTerm`, PS1's change to `src/gone.ts` taken back in PS2, is found in the gone file and Enter opens it on the removed row. With the base on the branch, `earlyTerm` is found again. |
| untraced-thread | #37 | Threads whose own commit no longer shares history with the base (the base rewritten, the PR rebuilt and force-pushed): one sits on GitHub's line with no chip; the one GitHub marks outdated is listed under its file as `outdated`, never `rewritten`. |
| thread-agent | #38 | The thread agent on "fixed in all places, or just here?": a thread on `src/profile.ts` asks for a fix "here and in every other place", one push fixes only `profile.ts`, a later one `mailer.ts`. Asked while viewing the partial fix, the agent says what's fixed there and calls out that the rest came later ("not in PS 1; fixed later, in PS 2"), with no Resolve By Agent Suggestion; asked on the head, it suggests resolving. Also the counter, the unread dot and the slide-over on a phone. |
| dense-rewrite | #39 | A minified bundle rewritten line for line (200 unrelated 1,000-character pairs): the lines show at once with a spinner in the sign's place while their word marks are computed in the background, no freeze; a second bundle with one name changed per line is marked on first paint. |
| similarity-pairing | #40 | Clusters with more lines on one side, where lines pair by similarity (word diff step 2): an item added to a list, a comment added above a change, a line removed from the middle, nothing similar (unchanged), a helper added above a renamed function, Myers's Clear/Touch mess, a made-up extract method. A pair is marked; unified puts its removed line right above its added one, Side by side on one row. |
| rename-long-path-file-comment | #41 | A file renamed from a 116-character path, with a 257-character line and a file-level comment: the "Renamed from …" label and the file's comment bubble never cover each other, on a phone too and with the diff scrolled sideways. |
| comment-in-hidden-lines | #42 | Three threads (two RIGHT, one LEFT) on lines behind a "N hidden lines" row: tapping its bubble opens them under the row and the lines stay hidden; showing the lines opens each on its own line. |
| carried-thread-rewritten-line | #43 | A thread on a line a later push rewrote and moved down two lines: on its current line, the thread's card shows the code it was written on, not the rewritten line. |
